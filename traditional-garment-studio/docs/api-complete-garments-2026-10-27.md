# 10月27日完整服饰接口增补

沿用`/api/v1/parse`的`innerwear_choice`、`skirt_choice`和`opening_choice`字段，不增加制版类型，仍22类/209组合。

## 同图多个待选项

受支持的整套若同时有一个直上缘内搭候选和一个被遮挡下裙候选，先返回`innerwear_choices`，本步仅接受该选择。保存观察经过全量核对后，返回新的`image_proposal_id`、`suggested_text`与`skirt_choices`。前端必须使用新令牌、新原文，仅传本步选择。最终全部确认后才生成全部衣物，不能因已选内搭而跳过下裙。

每一步继续带`scope=outfit`，不要重新上传或附原图。原观察只识别一次；选择来自用户，不算图片确认。缺选、混传、跨会话、过期或重复令牌均拒绝。旧有效纸样在待选过程中保持，最终生成后才替换；其它不支持结构仍要求补图。

前襟待选返回`opening_choice_name`（中文衣物名），用于说明当前选项属于哪件衣物。仅前襟遮挡可以待选，无袖或其它结构冲突仍拦截。

## 多件文字范围

当前一份设计只存一套，每类衣物一件。“两件褙子”、同款内外两层或两套请求返回`needs_input`，明确同款可以复用一份纸样，避免把两件去重为一件。明确单套上下装的“只做”不应被当成只制作局部；明确的来源领片/袖片/下裙范围保留。

## 预览排布

新整套生成含`preview-layout.json`，描述不旋转、不缩放的裁片预览平移位置、分件和尺寸预留框。根目录`preview*.svg`及`body-layout*.svg`采用同一紧凑排布；`pattern*.svg`仍为完整1:1制版净样，A4纸样仍读取独立原净样。几何、裁布份数、尺寸来源不因排布改变。

ZIP增加该可选排布记录，逐文件SHA和保存回执包含它。旧设计无此文件仍可恢复，不会被自动重新排布。新预览图不替代裁剪轮廓或打印方案。

## 网络中断恢复

`POST /parse`新增可选`request_id`，格式为16–64位字母、数字、短横线或下划线。每次新操作使用新值；如果提交响应丢失，重试保留同一值与完全相同的文字、图片引用、范围、建议令牌和选择。

同一后台运行期间，同会话的最近64个已接受请求复用原任务，不再识图或生成；运行中也可取回原任务ID。相同标识却改变内容返回409 `request_id_conflict`，不会执行变化的请求。标识不跨会话共享，也不是持久化的任务凭据；后端重启后失效。

已取得`task_id`后进度暂时不可读，前端“继续查看本次结果”只继续读取原`/tasks/{id}`，不再次调用`/parse`。若明确重新识图、确认建议过期、原图引用失效或后端重启，则清理旧操作标识，按提示重新开始。未传标识的既有客户端保持原接口行为。

## 云肩尺寸

应用参数增加`cloud-shoulder.petal_length`（肩宽比例0.15–0.9，默认0.28）与`front_extension`（原生厘米0–20，默认0）。`PUT /design/params`中前者可传`unit=cm`，后者直接传厘米；整套同样适用。厘米指定值随肩宽变化保留。前者是曲线大小基准，不是总直径或宽高，实际总尺寸见净样与裁片清单。单纯要求整件直径而未给可用参数时澄清，不忽略该要求。

视觉观察增加可选`cloud_coverage`：`neck`、`shoulders`、`chest`、`unclear`。前三种分别建议大小比例/前延伸0.22/0、0.38/0、0.38/10cm，来源`image_style_default`；它们是工程建议，不能当作照片测量。文字明确值优先。缺字段按`unclear`，非法枚举拒绝。

新云肩模板版本`cloud-basics-2026-10-27-v2`。旧`traditional-basics-2026-10-18`云肩从已保存轮廓推回原隐藏大小，延伸为0，新增来源`restored_geometry`；不重画或改写旧文件。冻结训练schema保持原层数、云头数、垂须长三个字段。
